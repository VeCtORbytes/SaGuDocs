## What it does

A `GraphMemoryStore` holds facts such as `(User) -[PREFERS_LANGUAGE]-> (TypeScript)`, each with `confidence`, `mentions`, `source`, `createdAt` and `updatedAt`. Agents use it in two ways:

| Mode | How | Who decides what's stored |
|---|---|---|
| **Automatic** | `agent.run(input, { longTermMemory })` with a [`LongTermMemory`](/docs/features/background-processes) | Background processes extract, link and clean facts; relevant facts are injected into every prompt |
| **Explicit tools** | `tools: createGraphMemoryTools(store)` | The model calls `remember_fact` / `recall_facts` |

You can combine both on one agent and one store.

## What problem it solves

Session history is long, linear and tied to one conversation. Facts are compact and reusable: a different agent, in a new session with no chat history, can still know that the user moved to Berlin and works on Atlas.

## Automatic mode

```ts
import { Agent, LongTermMemory, InMemoryGraphMemoryStore, anthropic } from "../src/index.ts";

const memory = new LongTermMemory({ store: new InMemoryGraphMemoryStore(), model: anthropic() });
memory.start();

const agent = new Agent({ name: "Assistant", instructions: "Help the user.", model: anthropic() });
await agent.run("I work on Atlas, which runs on Neo4j.", { longTermMemory: memory });
// … later, any session:
await agent.run("Which database should my next service use?", { longTermMemory: memory });

await memory.stop();
```

How extraction, inference and maintenance work: [Background graph processes](/docs/features/background-processes).

## Explicit tools

`createGraphMemoryTools(store)` returns two tools:

| Tool | Arguments | Does |
|---|---|---|
| `remember_fact` | `subject`, `predicate`, `object` (strings) | `store.remember({ subject, predicate, object, source: "tool:remember_fact" })` |
| `recall_facts` | `about` (string), `limit` (number, default 5) | `store.recall({ about, limit })`, returning `{ count, facts, summary }` |

From <Source path="examples/04-graph-memory-longterm-recall/index.ts" />:

```ts
import { Agent, InMemoryGraphMemoryStore, createGraphMemoryTools, anthropic } from "../src/index.ts";

const graphStore = new InMemoryGraphMemoryStore();
const graphTools = createGraphMemoryTools(graphStore);

const collector = new Agent({
  name: "ProfileCollector",
  instructions: "When users state preferences or project details, store them using remember_fact.",
  model: anthropic(),
  tools: graphTools,
});

const architect = new Agent({
  name: "ArchitectAssistant",
  instructions: "Before designing architectures, consult long-term memory using recall_facts.",
  model: anthropic(),
  tools: graphTools,
});

await collector.run("I exclusively write TypeScript and our database is PostgreSQL with Neo4j.");
await architect.run("What tech stack do you recommend for my next microservice?"); // no shared session
```

To switch to Neo4j without code changes, use `createAutoGraphMemoryStore()`. It returns a Neo4j store when `NEO4J_URI` is set, otherwise an in-memory one.

## How it works internally

- **Store operations:** `remember` (upsert: keeps `createdAt`, increments `mentions`, refreshes `updatedAt`), `recall`, `listFacts`, `forget`, `mergeEntities`, `close`.
- **Recall** matches the whole query **or any word of it** against subject, predicate and object, case-insensitively. Neo4j orders results by confidence.
- **Fact identity:** the in-memory store compares subject/predicate/object case-insensitively. Neo4j matches entity names exactly; the maintainer merges case variants.
- **Neo4j model:** `(:Entity {name})-[:RELATION {type, confidence, mentions, source, createdAt, updatedAt}]->(:Entity {name})`.

## Limitations

- **In-memory facts are lost on restart.** Use Neo4j for persistence.
- **`metadata` is not stored in Neo4j.**
- **Keyword recall, not semantic search.** Synonyms (`car` / `vehicle`) aren't matched.
- **Duplicates by meaning** (`PREFERS` vs `LIKES`) are not merged; duplicates by spelling are (see the [maintainer](/docs/features/background-processes#3--graphmaintainer)).
