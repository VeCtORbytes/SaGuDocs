## What it demonstrates

1. Agent runs that return in milliseconds while extraction happens later
2. `FactExtractor` turning two conversations into facts, including a reinforced repeat
3. `RelationshipBuilder` inferring a symmetric edge and two chain-rule edges
4. `GraphMaintainer` merging `type-script` into `TypeScript` and resolving `LIVES_IN Paris` vs `LIVES_IN Berlin`
5. A third, history-free run receiving the cleaned facts in its system prompt

## Key code

```ts
const store = await createAutoGraphMemoryStore();

const memory = new LongTermMemory({
  store,
  model: extractorModel, // scripted: returns the facts for each conversation
  relationships: { intervalMs: 400 },
  maintenance: { intervalMs: 800 },
});
memory.on((event) => console.log(describe(event)));
memory.start();

await assistant.run("I'm working on Atlas with my colleague Raj. It runs on neo4j. I live in Paris and prefer type-script.", {
  longTermMemory: memory,
  sessionId: "chat-1",
});
await assistant.run("I just moved to Berlin. Atlas also uses TypeScript.", { longTermMemory: memory, sessionId: "chat-2" });

// … wait for the processes, then a fresh run:
for await (const event of assistant.stream("Help me plan a database migration.", { longTermMemory: memory })) { … }

await memory.stop();
await store.close();
```

Timing and the exact order of background lines vary between runs, because the processes really are independent. With Neo4j, `Atlas USES neo4j` and `Atlas USES Neo4j` are stored separately until the maintainer merges them, because Neo4j entity names are case-sensitive.

## Walkthrough

- **Runs don't wait.** `run 1` returns while its conversation is still queued (`extraction queued: 1`).
- **Reinforcement.** `Atlas USES Neo4j` was said in both conversations: confidence 0.9 combined with 0.8 gives 0.98.
- **Inference.** `User WORKS_ON Atlas` plus `Atlas USES Neo4j` gives `User USES Neo4j` at 0.95 × 0.98 ≈ 0.93.
- **Maintenance.** `LIVES_IN` is single-valued, so the newer Berlin replaces Paris. `type-script` and `TypeScript` share a key, so they become one entity.
- **Retrieval.** Run 3 mentions none of these entities, but `User` is always looked up, so every fact about the user reaches the prompt, ranked by confidence.
